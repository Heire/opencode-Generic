Digitale onderhoudschecklist ANPR & CCTV

Van Excel naar een gestructureerde flow in Xurrent — wens, aanbeveling en realisatie
Opgesteld voor: Jacops Security — team Preventief Onderhoud / BI & IT  •  Datum: 13 oktober 2026  •  Platform: Xurrent (ticketing) + Microsoft 365 / Teams  •  Scope: Fase 0 — Xurrent-native (geen extra tooling of licentiekost)

1. Wat we wensen

Vandaag gebruiken we een Excel-formulier (JACOPS_Preventief_Onderhoud_ANPR_CCTV_V2.xlsx) als checklist voor preventief onderhoud aan ANPR- en CCTV-installaties. Dit werkt, maar is niet praktisch op terrein: moeilijk in te vullen op een gsm/tablet, foto's moeten manueel worden ingevoegd, GPS en handtekening gebeuren op papier, en het resultaat wordt nadien manueel overgetypt in het ticket.

De wens is daarom:

  • Een digitale checklist die de technieker op gsm/tablet invult tijdens de interventie.
  • De check direct gekoppeld aan het ticket in Xurrent (ticket de single source of truth).
  • De gegevens gestructureerd opgeslagen, zodat ze later ontsloten kunnen worden voor BI en voor het automatisch genereren van het interventieverslag via AI.
  • Maximaal gebruik van de bestaande ecosystemen (Xurrent + O365/Teams), zonder nu al een extra platform of licentie aan te kopen.

2. Kaders & uitgangspunten

  • Geen extra licentiekost in Fase 0. Alles wat op M365-licenties zit, is gratis; premium features (zie §7) stellen we uit.
  • Ticket blijft de bron van waarheid. De checklist hoort bij het ticket, niet in een los kanaal.
  • Gestructureerde data primeert: elke waarde wordt als veld/JSON opgeslagen en is API-ontsluitbaar.
  • Tweetalig (NL/FR) waar nodig, minstens in het eindrapport.

3. Aanbeveling: bouw het native in Xurrent

Xurrent heeft alle bouwstenen om jouw Excel dicht te benaderen — zonder extra tooling:

BouwsteenWaarvoor
Request templateRegistratie van de interventie
Workflow templateSplitst de beurt in opeenvolgende taken
Task templatesHerbruikbare deeltaken (info, kast, camera, as-built, …)
Checklist in InstructionsAfvinkbare lijst (aan/uit) op een taak — werkt ook in de mobiele app
UI Extension (Designer)Aangepaste velden: keuzelijsten (OK/NOK/WARN), tekst, datum, ja/nee, voorwaarden & validatie
Note + AttachmentsOpmerkingen en foto's als bijlage
Kernprincipe: de Instructions-checklist is enkel afvinken. Status (OK/NOK/WARN), meetwaarden en opmerkingen horen in UI-Extension-velden. Door beide te combineren krijg je een getrouwe weergave van de Excel, mét audit trail en ticketkoppeling.
Belangrijk: Xurrent heeft geen echt grid. De per-camera matrix lossen we op met één taak per camera in de workflow. Zo wordt de matrix opgesplitst in kleine, mobielvriendelijke taken, elk met eigen controles en foto's.

4. Welke flows per onderdeel

De volledige interventie wordt één workflow, opgebouwd uit één taak per onderdeel. Per onderdeel:

OnderdeelFlow / objectConfiguratie
Registratie Request template Subject, categorie, service, team; koppeling aan de workflow; instructie + registratiehints
1. Algemene info & locatie Taak + UI Extension Velden: ticket, site-ID, technicus, datum, uren, GPS (manueel), locatietype, camera-ID's
2. Checklist straatkast Taak + Instructions-checklist + UI Extension 16 punten als afvinklijst; UI Extension voor algemene status + afwijkende punten (nr, status, waarde, opmerking)
3. Camera's 1 taak per camera + checklist + UI Extension Per camera 5 controles (OK/NOK/WARN) + overall status + opmerking; foto's als bijlage op de taak
4. As-built inventaris Taak + UI Extension Merk/model, serienummer, IP, as-built OK? per component
5. Afwijkingen & acties Taak + UI Extension Schade, acties, ter plaatse hersteld?, offerte nodig?, vervangstuk nodig?
6. Clôture & afmelding Taak + UI Extension Afmeld-call, contactpersoon, tijdstip, zware schade gemeld?

5. Hoe we dit realiseren — stappenplan

Stap 1 — Voorbereiding (beheerder)

  • Team Techniekers PM aanmaken; service PM ANPR & CCTV aanmaken.
  • Rollen regelen: Account Administrator (UI Extensions), Account Designer (templates), Service Desk Manager (request templates).
  • Bouw alles eerst in de QA-account, daarna uitrollen naar productie.

Stap 2 — Templates aanmaken

  1. Request template JACOPS — PM ANPR & CCTV (velden + koppeling aan workflow).
  2. Workflow template JACOPS — PM ANPR & CCTV (workflow) met de 6 taken in volgorde.
  3. 6 taaktemplates aanmaken (naamgeving PM — nr. naam).

Stap 3 — Checklists plaatsen (Instructions)

In het Instructions-veld van de taaktemplates: regels typen, selecteren en omzetten naar checklist (icoon, zoals bij een bullet-lijst).

Stap 4 — UI Extensions bouwen (Designer)

Per taaktemplate één UI Extension (Settings > UI Extensions > Add > Designer) met secties, velden, voorwaarden en validatie. Voorbeeld van de veldmapping:

TaakVelden (voorbeeld)
1. Algemene infoTicket, site-ID, interventienr, datum, technicus, adres, gemeente, uren, contactpersoon, aantal kasten, GPS N/E, locatietype (select), camera-ID's
2. Checklist straatkastAlgemene status (OK/NOK/WARN), algemene opmerkingen, afwijkend punt (nr, status, waarde, opmerking)
3. CameraCamera-ID/positie, 5× status (OK/NOK/WARN), overall status, opmerkingen
4. As-builtMerk/model, serienr, IP, as-built OK? (Ja/Nee/N.v.t.), opmerking
5. AfwijkingenAfwijkingen, acties, ter plaatse hersteld?, offerte nodig?, vervangstuk nodig? (Ja/Nee)
6. ClôtureAfmeld-call, contactpersoon, tijdstip, zware schade gemeld? (Ja/Nee)
Ontwerpkeuze om te bevestigen: registreren we de status van alle 16 punten (16 keuzelijsten), of enkel de afwijkingen (lichter formulier)? Dit bepaalt de bouwinspanning.

Stap 5 — Foto's

  • Foto's als bijlage op de note van de betreffende taak (camera → camerataak).
  • Vaste conventie: notettitel FOTO <blok> — <omschrijving>, bv. FOTO 1.1 — Stuurkast interieur.
  • Fotoblokken: 1 Stuurkast · 2 Camera's · 3 Omgeving · 4 Schade.
  • Werkt rechtstreeks met de toestelcamera via de Xurrent mobiele app.

Stap 6 — Testen & uitrollen

  1. Testscenario's in QA: request registreren → taken gegenereerd? Mobiele app: checklist + velden + foto? Validatie blokkeert correct? Camera-taken correct?
  2. Uitrol naar productie via de UI-Extension reference (nu definitief vastleggen).
  3. Korte werkinstructie voorzien voor de techniekers.

6. Data-ontsluiting (BI) & AI-rapport

Alle UI-Extension-waarden worden opgeslagen als custom fields (JSON) op het record en zijn dus API-ontsluitbaar — geen extra tooling nodig.

ItemWaarde
Base URLhttps://api.xurrent.com/v1/
AuthenticatieOAuth2 (personal access token / client credentials)
Account-headerX-Xurrent-Account: <account>
Endpoints/requests, /tasks, /request_templates, /task_templates, Bulk API, Webhooks API

AI-rapport: de gestructureerde velden + checklist vormen samen de input voor een vaste AI-prompt die het interventieverslag in de eigen templatesjabloon genereert (NL/FR). Dit vermijdt een betaalde Word/PDF-flow.

8. Te beslissen vóór de bouw

  1. Status van alle 16 punten of enkel afwijkingen registreren?
  2. Aantal camerataken standaard (3? configureerbaar?)
  3. Tweetalig op elk veld of enkel op het eindrapport?
  4. Handtekeningen in scope? (native niet mogelijk)
  5. Koppeling aan Sites/CI's nu of later?

9. Definition of Done

  • De technieker kan in de mobiele app een volledige PM-beurt uitvoeren: checklist afvinken, status/waarden/opmerkingen invullen, foto's per type toevoegen.
  • Alle gegevens zijn gestructureerd (custom fields JSON) terug te vinden via de API.
  • Flow gedocumenteerd en getest in QA, uitgerold naar productie.
  • Werkinstructie + foto-conventie gekend bij de techniekers.
